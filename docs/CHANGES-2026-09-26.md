# Platform update — 26 September 2026

Summary of the fixes and new features in this update. Setup: [LOCAL-SETUP.md](LOCAL-SETUP.md).

## CMS edits that did not stick (fixed)

| Problem | Cause | Fix |
|---------|-------|-----|
| Tour edits disappeared after a restart | The 12 PDF packages were re-seeded over the tours on **every** start | Seeds and "upgrades" now run **once** per database (`meta.bootTasks`) |
| Lodge edits reverted; deleted posts/destinations/FAQs came back | The website catalog was merged back in on every start **and every dashboard visit** | Runs once; never on dashboard load |
| Cleared fields (gallery, highlights, itinerary) refilled themselves | Catalog "enrich" ran every start | Runs once |
| Published tours without a price silently unpublished on restart | Maintenance task ran every start | Runs once |
| Admin password reset to `.env` value on every restart | `seedDefaultUsers` rewrote the admin hash | Only creates the first admin on an empty database |
| "Save" refused on unfinished tours / group safaris | Draft saves required price, duration and a full itinerary | Drafts always save; the checks apply when **publishing** and are shown as warnings |
| CMS changes vanished from the website after a few page views | Each page made ~10 API calls and hit the 100/min rate limit, so the site fell back to old built-in text | One cached `/api/v1/site-bundle` request (ETag/304); read limits raised; forms have their own limit |
| Three lodges stored twice with the same id | Old seed merge | De-duplicated on import (newest copy kept) |
| Group safari page with a CMS slug different from its URL rendered empty | Slug overwritten when merging CMS data | Website URL kept, CMS slug used as an alias |

## Database

* Every CMS collection is stored in PostgreSQL (`cms_documents`), written transactionally; only changed rows are written.
* Staff users live in the relational `users` / `user_roles` tables.
* Uploaded photos are stored in PostgreSQL (`cms_media_blobs`) as well as on disk, so they survive redeploys.
* Existing `store.json` content and users are imported automatically on first start.
* Migrations run automatically at startup with the Node driver (no `psql` needed); `npm run db:setup` creates the database.
* Fixed schema drift in the relational mirror (`faqs.extras` missing; lodge category `premium-luxury` rejected).

## Photos

* Upload paths no longer depend on the folder the API was started from (Windows `uploads\…` paths broke on Linux/Render).
* Uploads are verified as real images (not just by file extension), auto-rotated, resized to 2000 px and converted to WebP. Multiple files at once.
* Deleting a gallery photo no longer renumbers/renames the other gallery files (which broke photos on other pages).
* Media library → **Needs attention** lists missing or empty image files (e.g. `kibo-palace-hotel*.webp`, `serengeti-explorer.webp`, `the-manor-at-ngorongoro.webp`).
* Broken images on the website fall back to a gallery photo instead of a broken icon; `-card` thumbnails fall back to the full photo.
* Images below the fold are lazy-loaded; the 4 MB hero video is skipped on phones, data-saver and 2G.

## Users & security

* Removed the development back door that gave **full admin access to any request without a token** when `NODE_ENV` was not `production`.
* Fixed stored XSS: names/messages from the public contact and booking forms were inserted into the CMS dashboard as HTML.
* Sessions are re-checked: disabling a user, changing their role or password signs them out immediately.
* Five roles (Super Admin, Admin, Manager, Editor, Viewer) manageable in **Users & roles**; delete, unlock, sign-out-everywhere; **My profile** for own password and email alerts.
* Password policy (10+ chars, mixed), login lockout after 5 failures, weak-password prompt after sign-in, constant-time login.
* JWT: no more well-known fallback signing key in production; algorithm pinned; token versioning.
* Demo editor/viewer accounts still using the published default passwords are disabled.
* Content-Security-Policy, HSTS (production), frame protection; canonical-host redirect.
* Public forms: HTML stripped, honeypot + fill-time spam checks, duplicate suppression, per-visitor limit.
* SMTP password, webhook secrets and review API keys are encrypted at rest (AES-256-GCM).

## Email & notifications

* All emails rewritten professionally; subjects and opening paragraphs editable in **Site settings → Email wording**.
* Footer contact details come from Site settings (not hard-coded).
* Staff alerts go to one or more addresses plus any staff member who switches alerts on.
* CMS notification bell: new inquiries, pending bookings, and system problems (email not configured, database not connected, failing integrations, review import errors).
* **System status** page with an SMTP connection check.

## Third-party integrations (webhooks)

* **Integrations & webhooks**: send `booking.created`, `inquiry.created`, `safari.published`, … to any HTTPS endpoint with HMAC signatures, custom headers, retries and a delivery log. See [api/webhooks.md](api/webhooks.md).

## Reviews

* **Guest reviews**: automatic import from Google (Places API) and TripAdvisor (Content API), paste import for SafariBookings, moderation, featured reviews, combined rating. See [cms/reviews.md](cms/reviews.md).
* Placeholder testimonials ("Traveler review — Rated 5/5 by served clients" etc.) were **unpublished** (not deleted); the site now shows real imported reviews.

## SEO

* Every page gets its own title, description, keywords, canonical, Open Graph/Twitter tags and JSON-LD (TravelAgency, TouristTrip + Offer, BlogPosting, TouristDestination, FAQPage, BreadcrumbList) **server-side**, so Google and link previews see them.
* `/sitemap.xml` (all published tours, destinations, posts and group safaris, with images) and `/robots.txt`.
* Pages in the CMS have SEO title / description / keywords / share image fields; tours, destinations and posts already had them.
* Real 404 pages (status 404 + noindex) instead of the home page on unknown URLs; trailing-slash redirects.
* Home H1 now describes the business ("Tanzania safaris, Kilimanjaro climbs & Zanzibar escapes").

## Speed

* Gzip compression; fingerprinted assets cached for a year; images 30 days; HTML revalidated.
* One site-bundle request instead of ten; blog bodies no longer downloaded on every page.
* Tour detail pages use the bundle instead of two more requests.
* Fonts loaded without inline scripts (CSP-compatible).

## Copy

* Rewrote the home, about, contact, tours, group safari and footer copy in a consistent, professional voice; removed unverifiable claims ("rated 5/5 by customers") and placeholder quotes.
* SEO defaults and page excerpts updated (only where they still had the original placeholder text).
